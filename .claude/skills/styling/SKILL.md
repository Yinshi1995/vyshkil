---

Стилюй компонент лише атомами `style`-крейту, не інлайн-стилями й не новим BEM-CSS.

1. Читай `style/ATOMS.md` (≤80 рядків) — НЕ `style/grammar_data.rs`, НЕ `docs/spec/08-style-system.md`
   (повний опис — лише якщо ATOMS.md реально не вистачило).
2. Склади рядок класів лише з атомів звідти: layout (`flex`/`gap2`/`items-c`), відступи (`p2`),
   колір ЛИШЕ через семантичні `fg-`/`bg-`/`bd-` (не `ink-N`/`gold-N` напряму).
3. Обгорни в `cx!("...")` (не голий рядок) — валідується компілятором, typo → підказка найближчого
   атома.
4. Стан/адаптив — префікс-варіант: `hover:bg-raised`, `md:cols-2`, не медіа-запит вручну.
5. Щільні поверхні (таблиці/сітки з багатьма рядками) лишай спокійними — без `shadow`/`bracket`/
   `chamfer` на кожному рядку (08 §6 "щільні поверхні спокійні").
6. Якщо потрібного атома НЕМАЄ: не імітуй inline-style-обхідним шляхом — додай атом у
   `grammar_data.rs` (08 §8), перегенеруй (`cargo run -p style --bin gen`), і ЛИШЕ ТОДІ вживай.
7. Нова fg/bg-пара кольору, якої нема в `style/src/contrast.rs::PAIRS` → додай туди, запусти
   `cargo test -p style` (WCAG-тест) ПЕРЕД комітом.

Після зміни — `cargo test -p style` зелений; візуальна перевірка компонента (скріншот) — окремо,
не щоразу.
