# Прод-доступ через Cloudflare tunnel

## Контекст

`docs/spec/11-prod-deploy.md` §0.2 забороняв публікацію через Cloudflare tunnel ("Цей застосунок
через цей (чи будь-який інший) Cloudflare tunnel не публікується ніколи").

## Рішення

Замовник змінив вимогу (2026-10-05): зовнішній доступ до прод-VM через Cloudflare tunnel
дозволено. Мотивація — зручний доступ з польових пристроїв без необхідності VPN.

## Реалізація, ревізія 2 (2026-10-05, вказівка замовника)

Першу версію (окремий `cloudflared` на прод-VM, власний токен) **скасовано**: замовник сказав
використати наявний `cf-connector` (LXC 150), який уже сидить у VyOS-сегменті, і сам прокидає
hostname у Cloudflare dashboard. Тому:

- на прод-VM `cloudflared` **не ставиться**, токен у Vault не потрібен;
- прод-VM — у власному VLAN 90 `VYSHKIL` (10.90.0.0/24) за VyOS, IP 10.90.0.10 (статика —
  на VyOS немає DHCP, усі сервіси в сегментах статичні, облік адрес — у конфігу VyOS);
- VyOS forward-правило: лише `10.10.0.5` (cf-connector) → `10.90.0.10:3000/tcp`;
- на VM порт 3000 опублікований на інтерфейсі VM (не 127.0.0.1), nftables пускає 3000 лише з
  `10.10.0.5`; 5432/4222/8222 — як і раніше тільки 127.0.0.1;
- окремий VLAN, а не WEB 20 поруч зі `striy-web`: ДСК-стек не ділить L2 з чужим застосунком
  (у межах одного VLAN VyOS-firewall трафік не бачить).
- Cloudflare Access policy — на боці замовника в dashboard.

## Що НЕ змінилось

- Жодних даних назовні, крім знеособлених WhatsApp-повідомлень через notifier
- Жодних ПІБ у логах/моніторингу
- `source_files/` на проді відсутні
- Секрети — лише через Ansible Vault
