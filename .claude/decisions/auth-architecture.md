# Архітектура автентифікації

## Контекст

Користувач запросив модуль авторизації: логін/пароль + FIDO2/passkey. Зараз система працює
в dev-режимі з вільним перемикачем актора (01 §6: "ActorSwitcher — dev-заміна автентифікації").

## Рішення

**Варіант A (обрано)**: повноцінний auth з argon2id + cookie-сесії + FIDO2 WebAuthn.

Альтернативи:
- B) Спрощений auth без FIDO2 — менше роботи, але FIDO2 потрібен замовнику.
- C) OAuth/OIDC через зовнішній IdP — порушує правило "жодних мережевих викликів назовні".

## Ключові рішення

1. **argon2id** (не bcrypt) — сучасний стандарт, рекомендація OWASP.
2. **Cookie session** (не JWT) — серверна сесія = відкликаність, менший розмір cookie.
3. **webauthn-rs** — Rust-бібліотека, без зовнішніх залежностей (CLAUDE.md).
4. **Etapність**: 10a (пароль) → 10b (FIDO2) — можна деплоїти 10a окремо.
5. **Dev-режим**: `ActorSwitcher` залишається за `DEV_MODE=1` env-змінною.
6. **display_name**: не ПІБ — CLAUDE.md: "людей поіменно не зберігати".
7. **Seed**: admin-акаунт через `INITIAL_ADMIN_PASSWORD` env-змінну, без дефолтного паролю.
