# Дві осі підпорядкування з історією + матеріалізоване транзитивне замикання

**Чому:** у реальних даних частина може бути одночасно штатно підпорядкована одному органу
й оперативно — іншому (110 омбр: 17 АК і 20 АК одночасно), і це підпорядкування змінюється в часі
(142/154/61/5/92/225 з 17 АК перейшли в 7 КШР у серпні). Рекурсивні CTE над `subordination` для
запитів "усі підлеглі X на дату D" були б повільними на гарячому шляху (звіти, форма введення).

**Як застосовувати:** `subordination(child_org_id, parent_org_id, axis, valid_from, valid_to)` з
`EXCLUDE USING gist` (потребує `btree_gist`) — періоди для одного `(child_org_id, axis)` не
перетинаються. `subordination_closure` (ancestor_id, descendant_id, axis, depth, valid_from, valid_to)
— **перебудовується цілком в одній транзакції** при будь-якій зміні `subordination` (частин — тисячі,
перебудова — мілісекунди). Запити по ієрархії йдуть тільки через `subordination_closure`
(`server/CLAUDE.md`), не рекурсивними CTE.
