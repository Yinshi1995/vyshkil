# Фаза 3: наближати legacy-значення до шкали токенів, не розширювати шкалу

## Контекст

`app/style/main.css` (ручна частина, до генератора — [[style-system-architecture]]) — точні
значення, виміряні з живого сайту striy.pp.ua ([[ui-visual-style-source]]), не круглі числа:
`.app-header { padding: 14px 24px }` (асиметрично), `.app-header__nav a { letter-spacing: 0.05em }`,
`.app-header__mark { border-radius: 50% }`, заголовки — `font-size: 18px`/`13px`/`12px`. Жодне з
цих значень не збігається з кроком `SPACE_SCALE`/`TEXT_SCALE`/`RADIUS_SCALE` (докладний перелік
розбіжностей — `docs/spec/08-style-system.md` §11).

## Розглянуті альтернативи

1. **Наближати до шкали** — рерайт компонента атомами з округленням до найближчого кроку
   (14px→p2=4px? ні — до найближчого ЗІ ШКАЛИ: 12px=p2, 24px=p3 тощо). Вигляд трохи зміщується
   відносно виміряного еталону.
2. **Розширювати шкалу під legacy** — додати точні пікселі (14px, 24px, 18px, 13px, 12px, 50%) як
   нові кроки шкали. Пиксель-точно, але шкала перестає бути малим закритим набором (08 §1) —
   росте під кожен старий компонент, а не під реальну повторювану потребу.

## Рішення

Наближати до шкали (варіант 1) — рішення користувача, 2026-09-29. Закритість шкали (08 §1
принцип "мала таблиця, не 500 токенів") важливіша за пиксель-точну відповідність еталону,
виміряному ДО існування цієї системи; невелике зміщення (одиниці пікселів) на реальному дизайні
непомітне, а розширення шкали "під кожен legacy-компонент" звело б нанівець сенс мати шкалу
взагалі (за першим прецедентом і другий/третій компонент попросять "свій" крок).

## Наслідки для Фази 3

- Компонент-за-компонентом: узяти виміряне значення → округлити до найближчого кроку
  `SPACE_SCALE`/`TEXT_SCALE`/`RADIUS_SCALE` → якщо кроку явно бракує (різниця відчутна на око, не
  1-2px) — це сигнал додати НОВИЙ ЗАГАЛЬНИЙ крок шкали (не одноразовий legacy-хак), задокументувати
  чому в коміті.
- Один компонент/сторінка — один коміт, зі скріншотом до/після (Playwright, не комітиться —
  лише для власної перевірки), стару CSS-декларацію видаляти одразу в тому ж коміті (не лишати
  мертвий BEM-клас "про всяк випадок").
