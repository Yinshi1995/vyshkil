# `<label for>` замість JS-forwarding для вибору файлу

## Контекст

Користувач повідомив: клік лівою кнопкою по зоні завантаження файлу не відкриває системний вибір
файлу (перетягування працює). Стара реалізація (`components::FileDropzone`): прихований `<input
type="file">` з `display:none` + клікабельна `<div role="button">`-обгортка, що програмно кликала
по інпуту (`el.click()`), з `stop_propagation()` на самому інпуті як захист від подвійного
спрацювання.

## Діагностика

Два Explore-агенти й один живий Playwright-прогін цієї сесії:
- Жодного глобального click/mousedown-обробника, що міг би "зʼїдати" клік, не знайдено — усі
  mousedown-listeners закриття по кліку поза (Combobox/Select/DatePicker/RowMenu/DateRangeCell)
  коректно перевіряють `event.target`.
- `parsing`-сигнал коректно скидається на всіх шляхах success/error (окрім одного реального гапу —
  див. нижче).
- **Живий клік по СТАРІЙ зоні в Playwright/Chromium ФАКТИЧНО відкривав системний діалог** —
  точний репорт користувача автоматизацією не відтворено (ймовірно інший браузер/вебвʼю/оточення).

## Рішення

Переробити незалежно від підтвердження точного репро: `display:none`-input + програмний `.click()`
— задокументовано ненадійний патерн у частині браузерів (прихований `display:none`-елемент іноді
не вважається "видимим достатньо" для відкриття системного діалогу через програмний виклик). Нова
реалізація — `<label>` ОБГОРТАЄ реальний `<input type="file">` (visually-hidden: `position:absolute;
opacity:0`, НЕ `display:none` — лишається в layout-дереві й фокусованим), той самий патерн, що вже
є в цьому кодбейзі для `components::Checkbox`. Клік будь-де в лейблі й клавіатура (Enter/Space на
сфокусованому інпуті) відкривають діалог НАТИВНО — нуль JS-форвардингу, нуль
`stop_propagation()`-захистів від самозамкнутого циклу.

Заразом виправлено дві реальні ненадійності старої реалізації, знайдені під час переробки:
- `input.value` ніколи не скидався → повторний вибір ТОГО САМОГО файлу не шле `change`;
- `read_file_bytes`'s `array_buffer()`-відмова мовчки ковталась (`let Ok(buf) = ... else { return
  }`) → `parsing`-сигнал міг застрягнути `true` назавжди без жодної помилки користувачу.

## Альтернативи

- **Залишити JS-форвардинг, шукати конкретний браузер/причину глибше**: відхилено — навіть якби
  знайшли причину, `display:none`+`.click()` лишався б крихким патерном для БУДЬ-ЯКОГО майбутнього
  браузерного оточення; `<label for>` — стандартний, найнадійніший спосіб, який користувач сам
  попросив.
- **`visually-hidden` без `<label>`-обгортки, зі власним `on:click` на видимому елементі**: та сама
  крихкість, що стара реалізація (JS має вирішувати, куди "переслати" клік) — відкинуто.

  вводу).
