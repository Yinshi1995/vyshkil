# SeaORM замість Diesel

Обрано SeaORM як ORM для проєкту.

**Чому:** сервер уже на async-стеку (tokio, Axum, Leptos server functions). Diesel історично синхронний
і вимагає або блокуючого пулу з `spawn_blocking`, або сторонніх async-обгорток. SeaORM асинхронний
нативно (`sqlx`-сумісний драйвер під капотом), тому не потрібен додатковий шар для сумісності з async-рантаймом.

**Альтернативи, які розглядались:** Diesel (синхронний, сильніша типізація на етапі компіляції, але
незручний в async-контексті), sqlx напряму без ORM (менше магії, але довше писати CRUD і міграції вручну).

**Ціна:** SeaORM генерує більше runtime-перевірок типів порівняно з Diesel's compile-time query checking.
