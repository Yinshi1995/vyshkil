# Кількості тільки подіями (event sourcing), бітемпорально

**Чому:** "нічого не перезаписуємо — все має історію" (`01-domain-model.md`, принцип №2). Якщо
кількість у групі зберігати полем і апдейтити, губиться історія "хто, коли і що саме змінив" —
а це критично для відтворення документів, відправлених у минулому ("як ми знали на момент T").

**Як застосовувати:** `group_event` (`planned/arrived/started/added/attrition/completed/
vos_awarded/…`) — єдине джерело кількостей; `training_group` не має власних полів-лічильників.
Кожна подія має `occurred_on` (коли сталося) **і** `recorded_at` (коли дізналися) — бітемпоральність:
похідні величини (`in_training(D)`, `finishing_on(D)` тощо) рахуються з фільтром і по `occurred_on`,
і, окремо, по `recorded_at ≤ T` для реконструкції минулого стану. `daily_counts` — лише матеріалізація
для швидких звітів, перераховується інкрементально; вона не є джерелом істини.
