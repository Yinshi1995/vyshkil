# Windows Smart App Control блокує локальну збірку — перевірка через Docker замість цього

На машині розробника ввімкнено Windows Smart App Control
(`HKLM:\SYSTEM\CurrentControlSet\Control\CI\Policy!VerifiedAndReputablePolicyState = 1`,
машина не в домені — це не enterprise WDAC, а саме споживацька Smart App Control).
Вона блокує виконання непідписаних, невідомих хмарній репутації бінарників — а кожен
Rust build-script (`build-script-build.exe`) унікальний і локально скомпільований, тому
випадково потрапляє під блок (`os error 4551`, "An Application Control policy has blocked
this file"). Це проявлялось непередбачувано: то `parking_lot_core`, то `wasm-bindgen-shared`,
то `zerocopy` — залежно від того, чи конкретний білд-скрипт уже колись успішно виконувався
на цій машині (і тому мав репутацію) чи ні.

**Обхідний шлях, що спрацював:** для `cargo-leptos` — не `cargo install` (компіляція з
вихідників, десятки нових білд-скриптів), а офіційний прероблений реліз-бінарник з GitHub
Releases (`cargo-leptos-x86_64-pc-windows-msvc.tar.gz`, перевірений по sha256). Такий шлях
не завжди доступний (не для всіх інструментів є прероблені релізи).

**Оновлення:** користувач пізніше сам вирішив вимкнути Smart App Control (усвідомлюючи
одностороннсть — назад тільки через перевстановлення Windows). Вимкнено через реєстр
(`VerifiedAndReputablePolicyState = 0`, елевований PowerShell). Компіляція (build-scripts)
запрацювала одразу без ребута; але власне ЗАПУСК скомпільованого `server.exe` все одно
блокувався до перезавантаження — Code Integrity policy зчитується в ядро при старті і
кешується в пам'яті, реєстр сам по собі не звільняє вже завантажену політику. Після
перезавантаження все запрацювало: локальний `cargo leptos build` + прямий запуск
`target/debug/server.exe` проти Postgres у Docker — без жодних блоків.

**Висновок:** якщо на машині можна вимкнути Smart App Control (і користувач свідомо на
це йде) — перезавантаження обов'язкове після вимкнення, інакше запуск нових бінарників
лишається заблокованим навіть при вимкненій політиці в реєстрі.

**Наслідок на майбутнє:** будь-який інший інструмент, що встановлюється через `cargo install`
(наприклад `cargo-modules`, див. [[cargo-modules-over-graphify]]), може впертися в той самий
блок. Спершу шукати офіційний прероблений реліз-бінарник; якщо немає — збирати всередині
Docker-контейнера, а не на хості.
