# cargo-modules замість Graphify для графа коду

Початковий запит просив поставити "Graphify або аналог" для графа залежностей коду.
Перевірка реєстру перед встановленням (як і просили) виявила проблему: "Graphify" — свіжий,
агресивно розрекламований продукт (кілька сайтів-двійників graphify.com/graphify.net з майже
ідентичним маркетинговим текстом типу "cuts token usage up to 49x", npm-пакет нещодавно
перейменований `graphifyy` → `@sentropic/graphify`). Його інтеграція з Claude Code ставить
PreToolUse hook, який виконує довільний код на кожен виклик інструменту — це і є canonical
supply-chain risk profile (свіжий, невідомий постачальник + автоматичне виконання коду на
кожному кроці агента).

**Рішення:** не встановлювати Graphify. Замість нього — `cargo-modules` (crates.io,
Rust-специфічний, давно існує, будує граф залежностей модулів/типів/викликів через
`rustc`/`rust-analyzer`, без hooks, що виконують код автоматично). Викликається вручну
командою (`cargo modules dependencies`, `cargo modules structure`), а не через
жорстко прописане правило "завжди читай перед усім" — саме цю пастку явно просили уникнути
в оригінальному запиті.

**Обмеження:** cargo-modules дає структурний граф Rust-коду (модулі/типи/виклики), а не
крос-мовний семантичний граф з натуральномовними summary, як обіцяє Graphify. Для суто
Rust-воркспейсу цього достатньо.

**Статус:** інструмент ще не встановлений локально — встановлення (`cargo install cargo-modules`)
вимагає робочого MSVC-лінкера, який на момент цього рішення ще ставився (див. MEMORY.md).
