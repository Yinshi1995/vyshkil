# 08. Стильова система

Власний, тонкий, статично типізований шар над CSS: Rust-дані (токени, граматика атомів) →
CSS-генератор → `cx!("...")` проц-макрос, що перевіряє клас-рядки на етапі компіляції. Не
Tailwind/UnoCSS (зовнішній бінарник/Node — заборонено, 00-agent-brief.md), не бібліотека
CSS-in-JS (нема рантайму на клієнті поза WASM, SSR без Node). Референси — atomiccss.dev
(терсова граматика), shadcn/ui (headless-логіка окремо від рецептів), Open Props (шкали токенів),
Pico.css (пристойний дефолт) — усі як натхнення, жодного як залежність.

**Чому не Tailwind через leptos-tailwind/Vite** (порада іншої моделі, відхилена користувачем):
зовнішній бінарник або Node.js у стеку (заборонено), класи — неперевірені рядки (жодної
компіляторної підказки при друкарській помилці). Contra-аргумент "за" не знайдено під час
дослідження Фази 0 — Tailwind CLI сам собою офлайн-здатний (бінарник без мережі), але все одно
зовнішній бінарник поза `cargo`, а класи лишаються рядками без перевірки типів. Рішення
підтверджено.

## 1. Мета і принципи

1. **Токени — єдине джерело значень.** Жоден колір/відступ/радіус не з'являється як літерал поза
   `style::TOKENS`. Порушення ловить архітектурний тест (Фаза 4).
2. **Атоми — терсова граматика, не довільний CSS.** `p4`, не `padding: 16px`. Значення атома —
   завжди `var(--токен)` або bare-keyword (`display: flex` і подібне, де немає шкали).
3. **Компілятор — документація.** Друкарська помилка в `cx!(...)` — помилка компіляції з
   підказкою найближчого правильного імені, не мовчазний рядок без стилю.
4. **Рецепт раніше за повторення.** Той самий набір атомів утретє — привід зробити рецепт
   (`Button`, `Panel`, `Tag::Unit`), не копіювати `cx!(...)` вчетверте.
5. **Військова мова — інструментальна, не костюмна** (§5). Щільні поверхні — без декору (§6).
6. **Один файл на виході.** `cargo-leptos` не розгортає `@import` і обробляє `style-file`
   **до** збірки Rust-крейта `app` (емпірично підтверджено:
   `.claude/decisions/css-colocation-deferred.md`, і повторно в Фазі 0 цього документа) — генератор
   сам конкатенує все (reset+tokens+base+components+atoms+overrides) в ОДИН фізичний файл, не
   покладається на препроцесор.

## 2. Токени

Два рівні. **Примітивні** — сирі значення (шкали). **Семантичні** — іменовані ролі, що
посилаються на примітивні (щоб тема могла підмінити семантичний рівень, не чіпаючи примітивний).

Палітра й шрифти — ті самі виміряні зі striy.pp.ua значення, що вже в `app/style/main.css`
(`.claude/decisions/ui-visual-style-source.md`), **не вигадані заново** — стильова система їх
переносить у Rust-дані, не змінює.

### 2.1 Примітивні токени (повний список — Фаза 1; Фаза 0 прототипувала підмножину з 11)

| Шкала | Токени |
|---|---|
| `space-{0..8}` | 0, 4, 8, 12, 16, 24, 32, 48, 64 px |
| `radius-{0..3}` | 0, 4, 8, 999px (pill) |
| колір "олива/хакі" (`ok`) | `olive-{1..3}` (приглушені зелені) |
| колір "бурштин" (`warn`) | `amber-{1..3}` |
| колір "цегла" (`danger`) | `brick-{1..3}` (= поточний `--error: #c97a6e`) |
| колір "сталь" (`info`) | `steel-{1..3}` |
| колір "золото" (акцент) | `gold-{1..3}` (= поточний `--accent: #c9a84c`) |
| нейтральні | `ink-{0..4}` (= `bg-darkest`/`panel`/`panel-alt`/`text-main`/`text-muted`/`text-muted-2`) |
| типографічна шкала | `text-{xs,sm,md,lg,xl,display}` (px+line-height пара) |
| вага шрифту | `weight-{4,5,7}` (regular/medium/bold) |
| тінь | `shadow-{0,1,2}` |
| z-індекс | `z-{dropdown,overlay,modal,toast}` (іменовані, не числа — уникає "хто вище" воєн) |
| тривалість | `duration-{fast,base,slow}` (120/200/320ms) |

## 3. Граматика атомів

Одна таблиця — джерело для генератора CSS, `cx!`-валідації, `style/ATOMS.md`-шпаргалки й
архітектурного тесту (Фаза 4). Формат: `сімейство{шкала}` → CSS-властивість.

| Сімейство | Приклади | CSS-властивість |
|---|---|---|
| `p`,`px`,`py`,`pt`,`pr`,`pb`,`pl` + `{0..8}` | `p4`, `px2` | padding (усі сторони/осі/окремо) |
| `m`,`mx`,`my`,`mt`,`mr`,`mb`,`ml` + `{0..8}` | `mt1` | margin |
| `gap` + `{0..8}` | `gap3` | gap |
| `flex`,`col`,`row`,`grid`,`cols-{1..6}` | `grid cols-3` | display/flex-direction/grid-template-columns |
| `items-{s,c,e,b}`,`justify-{s,c,e,b}` | `items-c justify-b` | align/justify-items (start/center/end/between) |
| `w-{full,auto,px}`,`maxw-{prose,full}` | `w-full maxw-prose` | width/max-width |
| `t-{xs,sm,md,lg,xl,display}` | `t-lg` | font-size+line-height зі шкали §2.1 |
| `fw{4,5,7}` | `fw7` | font-weight |
| `up` | — | text-transform: uppercase |
| `track-wide` | — | letter-spacing: 0.08em (трафаретний військовий підпис) |
| `num` | — | font-variant-numeric: tabular-nums (щільні таблиці, колонки чисел не "гуляють") |
| `mono` | — | font-family: моноширинний (бірки частин, `<kbd>`) |
| `head` | — | font-family: var(--font-heading) (Oswald) |
| `fg-{main,muted,accent,ok,warn,danger,info}` | `fg-muted` | color |
| `bg-{base,panel,raised}` | `bg-panel` | background |
| `bd`,`bd-accent` | — | border: 1px solid var(--border\|--border-strong) |
| `r{0..3}` | `r1` | border-radius зі шкали §2.1 |
| `chamfer` | — | `clip-path: polygon(...)` скошений кут (той самий мотив, що зараз `.btn`) |
| `bracket` | — | тактичні кутові скоби (псевдоелементи `::before`/`::after`, §5) |
| `shadow{0,1,2}` | — | box-shadow зі шкали |
| `z-{dropdown,overlay,modal,toast}` | — | z-index (іменований) |
| `duration-{fast,base,slow}` | — | transition-duration |

### 3.1 Варіанти

Обмежений набір префіксів, застосовних до БУДЬ-ЯКОГО атома: `hover:`, `focus-visible:`, `active:`,
`disabled:`, `invalid:` (мапиться на `[aria-invalid="true"]`, не псевдоклас `:invalid` — форми тут
не нативна HTML-валідація), `open:` (мапиться на `[data-state="open"]`), `md:`, `lg:` (min-width
медіа-запити), `@md:` (container query, для карток/панелей незалежно від viewport). Генератор
екранує `:` у імені класу (`.hover\:bg-panel:hover { ... }`) — перевірено в Фазі 0, стандартна й
валідна CSS-техніка (той самий підхід, що й Tailwind).

**Фаза-0-обмеження**: мікро-прототип НЕ мав варіантів (20 атомів — лише базові). Синтаксис
екранування класу підтверджено технічно можливим, сама генерація префіксованих правил —
Фаза 1.

## 4. Теми

`data-theme` на `<html>`, вибір на сервері (cookie), рендериться в SSR одразу — без "блимання"
теми при гідратації (клієнт ніколи не перемикає тему вже після першого фарбування).

| Тема | Призначення |
|---|---|
| `night` (за замовчуванням) | Поточна палітра — темна, золотий акцент. |
| `day` | Високий контраст для яскравого приміщення (штаб при денному світлі). |
| `print` | Друк таблиць — без темного тла, максимальна економія тонера, кольори лише де несуть сенс (статуси). |

Тема міняє лише СЕМАНТИЧНИЙ рівень токенів (§2.2) — примітивні (сама шкала кольорів/відступів)
не змінюються. `ok`/`warn`/`danger`/`info` (польові тони) навмисно НЕ залежать від теми — статус
має читатись однаково в night і day.

## 5. Військова мова — інструментальна, не костюмна

Джерела: striy.pp.ua (виміряно раніше), `docs/templates/presentation-style.pptx`.

**Do:**
- Трафаретні uppercase-заголовки з розрядкою літер (`up track-wide`) — для заголовків розділів,
  не для абзаців тексту.
- Тактичні кутові скоби (`bracket`) — навколо КЛЮЧОВИХ панелей (KPI, статус подання), не навколо
  кожної картки підряд.
- Скошений кут (`chamfer`) — кнопки дій (уже є в `.btn`), не інпути/таблиці.
- Бірки номера частини (`Tag::Unit`, напр. "А4007") — стилізовані як маркування на техніці
  (моноширинний шрифт, тонка рамка), скрізь, де номер частини — окремий факт, не частина фрази.
- `<kbd>` як "шильдик обладнання" — той самий мотив, що бірка частини, для клавіш (уже є
  `.cheat-sheet__key`).
- Статуси — приглушені польові тони (ok=олива, warn=бурштин, danger=цегла, info=сталь), НЕ
  світлофорні яскраві RGB.

**Don't:**
- Не декорувати щільні поверхні (§6) — жодних скосів/скоб/трафаретних заголовків усередині сітки
  вводу чи таблиці.
- Не використовувати мілітарі-мотив як прикрасу без функції (скошений кут на елементі, що не є
  дією, — просто шум).
- Не вигадувати нову палітру "для настрою" — лише польові тони з §2.1, усі мають пройти AA (§7).

## 6. Щільні поверхні

Сітка введення (`widgets::group_grid::Grid`), таблиці імпорту, майбутні таблиці розбіжностей —
БЕЗ декору: без `chamfer`, без `bracket`, компактна щільність (`density-compact`), табличні цифри
(`num`), чіткий видимий фокус (`focus-ring`, обов'язково — це робоча поверхня, не вітрина).
Декор (§5 "Do") — лише в навігації, заголовках сторінок, картках KPI, стайлгайді.

## 7. Доступність

- Юніт-тест у крейті `style` рахує WCAG-контраст для КОЖНОЇ семантичної пари fg/bg у КОЖНІЙ темі:
  звичайний текст ≥ 4.5:1, великий текст/UI-межі ≥ 3:1 — падає з поясненням, яка пара і скільки
  бракує (Фаза 1).
- `:focus-visible` скрізь, де є `hover:` — фокус для клавіатури не менш помітний за courser hover.
- `prefers-reduced-motion` — `duration-*` атоми обнуляються в генераторі під цей медіа-запит.
- Логічні властивості (`padding-inline`, не `padding-left`/`padding-right`) — готовність до
  дзеркалення, навіть якщо RTL не планується найближче.

## 8. Рецепти

Headless-логіка компонента (вже є: `components::Select`, автокомпліт, `group_grid::Grid`,
шпаргалка, командна палітра) окремо від візуального рецепта. Рецепт — Rust-функція/структура з
варіантами → рядок класів (той самий мотив, що shadcn/ui, без React):

```rust
enum ButtonVariant { Primary, Outline, Ghost }
enum ButtonSize { Sm, Md }
fn button_classes(variant: ButtonVariant, size: ButtonSize) -> &'static str { /* cx!(...) за варіантом */ }
```

Стилі рецепта — у `@layer components`, лише через токени; co-located `*.css` поруч з компонентом,
коли CSS-колокація стане доцільною (07-code-structure — той самий бар'єр "~300 рядків", що вже
описаний для `.rs`).

## 9. Постачання CSS (Фаза 0 — критична знахідка)

`cargo-leptos` (перевірено емпірично двічі — `.claude/decisions/css-colocation-deferred.md` і
повторно тут): style-крок ("Build style") паралельний і НЕЗАЛЕЖНИЙ від збірки Rust-крейта ("Build
front"/"Build server" — форкаються з тієї самої точки, `_autodocs/api-reference/compile.md`:
`style` не чекає на `wasm`/`bin`). Тому:
- **`build.rs`-генерація НЕ ПРАЦЮЄ**: `build.rs` виконується під час `cargo build` крейта `app`,
  а `cargo-leptos` уже прочитав `style-file` ДО цього (перегони, стабільно відтворювані, не
  "перша холодна збірка").
- **`@import` не розгортається** Lightning CSS-кроком цього проєкту (`style_bundle` не увімкнено
  в `[[workspace.metadata.leptos]]`) — перевірено раніше, підтверджено актуальним.
- **Рішення**: генератор — ОКРЕМИЙ явний крок (`cargo run -p style --bin gen` чи аналог),
  запускається ВРУЧНУ (або обгорнутий у простий PowerShell/`Makefile`-скрипт, без Node) ПЕРЕД
  `cargo leptos build`, і сам конкатенує все (reset+tokens+base+components+atoms+overrides) в один
  фізичний файл, що Є (не `@import`-ить) `style-file` з `Cargo.toml`. Дублює логіку `@import`,
  яку мав би робити препроцесор, — свідомо, бо препроцесор цього не робить.
- Постачання: почати з ПОВНОГО набору атомів (шкали скінченні, `generate_css()` дешевий), заміряти
  розмір після gzip; сканер "лише використані класи" (build.rs зі скануванням `.rs`-файлів) —
  лише якщо розмір реально виправдовує складність (Фаза 1 рішення за фактом виміру).

## 10. Як додати

- **Новий атом**: рядок у таблиці граматики (`style::ATOMS`, Фаза 1 — єдине джерело для генератора
  й `cx!`, Фаза 0 має дубльовану копію між `style`/`style_macros` — задокументоване обмеження
  прототипу, `.claude/decisions/style-system-architecture.md`). Значення — лише `var(--токен)`.
- **Новий токен**: рядок у `style::TOKENS` (примітивний) або семантичній мапі (Фаза 1). Колір —
  ЛИШЕ якщо не досяжний через `color-mix()` з наявного.
- **Новий рецепт**: коли той самий набір атомів повторюється втретє (§1.4) — `components/CLAUDE.md`
  документує, як писати рецепт.

## Технічна перевірка (Фаза 0, емпірично на цій машині)

- `class=cx!("...")` — Leptos 0.7 приймає `&'static str` від проц-макроса без додаткової обгортки
  (перевірено: `style/tests/button.rs`).
- SSR-рендер у звичайний рядок ПОЗА `app/`/axum: **не** `leptos::ssr::render_to_string` (такого
  шляху немає в 0.7 — застаріла назва з 0.6) — реальний виклик: `ComponentFn().to_html()`
  (`tachys::view::RenderHtml::to_html`, доступний через `leptos::prelude::*`).
  Підтверджено рендером у `style/tests/button.rs` + `style/examples/preview.rs`
  (скриншот — окремо показано користувачу поза цим документом).
  `.to_html()` вимагає фічу `ssr` увімкненою на `leptos` (у `style`— лише в dev-залежностях,
  бо прототип не рантайм-частина застосунку).
  Не потребує ні DOM (wasm), ні Axum-сервера, ні `app/` — чиста функція.
- Проц-макро-крейт (`syn`+`quote`+`proc-macro2`, ті самі версії, що вже кешовані через
  `leptos_macro`) компілюється офлайн, ~3с холодний `cargo check` двох нових крейтів разом
  (Windows, цей хост) — не проблема.
- `cx!("p33")` (невідомий атом) — реальна помилка компіляції з підказкою: `невідомий атом «p33» —
  може, ви мали на увазі «p3»?`, вказує точно на рядок-літерал. Перевірено навмисним typo в тесті
  й відкатом.
- Власний юніт-тест "усе атомне значення — через var(--токен)" зловив РЕАЛЬНЕ порушення при
  першому write (`r1: border-radius: 4px` літералом) до того, як воно потрапило кудись далі —
  підтверджує, що правило (і його автоматична перевірка) справді щось ловить, не просто
  папероваа формальність.
