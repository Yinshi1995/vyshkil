# 03. Імпорт і валідація

Приймаємо **будь-що**: xlsx/xls/csv, docx, pdf (текстовий), скани (pdf-картинка, jpg/png).
Жоден файл не пишеться в канонічні дані напряму: завжди **превʼю → виправлення → фіксація**.

## 1. Конвеєр

```
файл ─► stored_file (sha256, оригінал на диску)
     ─► екстрактор за типом ─► "сира таблиця" (рядки × клітинки, з координатами джерела)
     ─► детектор структури (де заголовок, де дані, де підсумки/підписи)
     ─► зіставлення колонок (column mapping) з пам'яттю шаблонів
     ─► нормалізація значень (синоніми, дати, числа)
     ─► валідація (помилки/попередження на рівні клітинки, рядка, файлу)
     ─► ПРЕВʼЮ для користувача (редагування прямо в превʼю)
     ─► фіксація: submission.status = committed, reported_* → зіставлення → канон (див. 04)
```

## 2. Екстрактори

| Тип | Інструмент (перевір актуальність і ліцензію перед додаванням) |
|---|---|
| xlsx/xls/ods | `calamine` (Rust). Обовʼязково: **розгортати об'єднані клітинки** (значення з лівої верхньої копіюється в усі клітинки діапазону — у "Термінах" підрозділ об'єднаний на 25 рядків), читати і значення, і формули (формула = ознака рядка-підсумку), кешовані значення формул |
| csv | з автовизначенням кодування (UTF-8 / CP1251) і роздільника |
| docx | таблиці + абзаци (`docx-rs` або розбір `document.xml`) |
| pdf текстовий | витяг тексту з координатами, реконструкція таблиць по колонках |
| скан / pdf-картинка | OCR **локально** (Tesseract з мовою `ukr`+`eng`, без жодних зовнішніх API — дані ДСК). Результат OCR — та сама "сира таблиця", але кожна клітинка має `ocr_confidence`; низька впевненість = попередження в превʼю |

## 3. Детектор структури

- Рядок заголовка: найбільше збігів із відомими назвами колонок (`column_synonym`: "Підрозділ"≈"Військова
  частина"≈"ВЧ"; "Посада"≈"Спеціальність"≈"Спеціальність (напрямок підготовки)"; "Термін з"≈"Дата початку"…).
  Заголовок буває дворівневим (об'єднані "БЗВП" над "Кількість / Терміни / Місце…") — склеювати рівні.
- Пропускати: рядки-підсумки ("Всього за…", "… Підсумок", "ВСЬОГО", "РАЗОМ", рядки з формулами SUM),
  підписи ("Начальник відділу підготовки…", "полковник …"), гриф і службові рядки ("Для службового
  користування", "Прим. №1", "Вик.1 прим. на АБАК…", "Виконано без чернеток"), порожні рядки.
  Пропущене показувати в превʼю згорнутим списком "пропущено 12 рядків: підсумки, підписи" — щоб
  користувач бачив, що нічого не загубилось.
- Секції всередині аркуша ("Частини безпосереднього підпорядкування" / "…оперативного підпорядкування",
  "Військові частини … поза смугою") — зчитувати як **контекст рядків**, а не як дані.
- Кілька аркушів ("Пройшли" / "Проходять", "Завершилась" / "Навчаються", аркуш на кожен день) —
  кожен аркуш зі своїм смислом (завершені / поточні / стан на дату).

## 4. Нормалізація значень

- **Дати**: `dd.mm`, `dd.mm.yy`, `dd.mm.yyyy`, з крапкою в кінці (`16.08.`), діапазони в одній
  клітинці (`18.08-09.10`, `18.08 – 09.10`, `31.08 - 23.10\n`), справжні Excel-дати. Рік без явного
  вказання — з `as_of_date` подання: якщо дата виходить більше ніж на ~6 місяців уперед від
  `as_of_date`, це минулий рік (для "по" — навпаки, перехід через Новий рік: `15.12-20.01`).
- **Числа**: ціле ≥ 0; "12 (з 15.09…)" → число + решта в примітку; порожньо ≠ 0 (відсутність даних).
- **Клітинка "ВОС + посада"** ("ВОС 878\nБойовий медик взводу", "Кухар ВОС-788", "механік, (ВОС-460,
  КОД-256), Р-402, Р-425С3…") → окремо ВОС, посада, ОВТ, решта.
- **Частина/місце** ("241 обр ТрО\n(А4076)", "А3321 242 НЦ", "184 нц (356 нап, А3618, с. Старичі)",
  "А1556 (128 огшбр) А4007, н.п. Оріховиця", "польша", "м. Дніпро") → через `alias`; номер у тексті
  має пріоритет над назвою; населений пункт → `training_site.locality`.
- **Розподіл** ("1б тро-2\n2б тро-3\nупр-9", "1 мб - 3\n2 мб - 5", "БпЛА - 5  РЕР - 3") → `group_composition`.
- **Примітки** — вільний текст зберігаємо як є, але **намагаємось виділити події**: "2 вс СЗЧ",
  "1 в/с відрахований", "5 вс додались до курсу 24.08", "помилково записаний 1 вс", "не пройшов
  вхідний контроль" → пропозиції `group_event` у превʼю (користувач підтверджує). Шаблони — з
  1400 реальних приміток у "Контрольці" (див. source-analysis).
- Сміттєві плейсхолдери `-----`, `-`, `(пусто)`, `,` → порожнє значення.
- Обрізані багаторядкові значення ("посвідчення водія)", "(оператор)", "(рівень)") → попередження
  "схоже на обрізаний текст" + пропозиція повного значення з довідника.

## 5. Правила валідації

**Помилки** (блокують фіксацію рядка):
- неіснуюча дата (`31.09`), неможливий рік (`11.07.2027` у звіті за 2026, `18.09.20216`);
- "по" раніше "з";
- кількість не ціле / від'ємна; "Навчаються" > "Прибуло" > "План" (порядок воронки порушено);
- сума `group_composition` ≠ кількість групи;
- ВОС не з довідника і не схожий ні на що (`545543` — два коди злиплись → пропонувати 545 або 543);
- частина/місце не розпізнано і не вибрано вручну;
- у фаховій без ВОС і без курсу (для інструкторських курсів ВОС не потрібен — див. правила нижче);
- у рядку є ПІБ-подібний текст (прізвище великими літерами + ім'я) у полях, які потрапляють у БД —
  вирізати і попередити (людей не зберігаємо).

**Попередження** (не блокують):
- тривалість нетипова для цього ВОС/курсу (за історією) або < 3 днів / > 120 днів;
- група з таким самим ключем (відправник + ВОС/курс + місце + початок ±3 дні) вже існує → "можливо,
  дубль/оновлення" з кнопкою "це оновлення тієї самої групи";
- номер частини в тексті суперечить назві ("110 омбр (А4007)" і "44 омбр (А4007)");
- ВОС не узгоджується з посадою/ОВТ (за `vos_position`/`equipment_vos`): "ВОС 403 + радіотелефоніст" —
  типово 420;
- дата "станом на" подання пізніша за сьогодні або давніша за 30 днів.

**Бізнес-правила з інструкції "Дельти"** (source-analysis):
- БЗВП: програма обов'язкова (БЗВП-3, -6, УДЗ, КТЗ).
- Фахова зараховується як здобута тільки з наказом про присвоєння ВОС (`vos_awarded` з номером наказу).
- Фахова на базі власної ВЧ — лише для 7-денних програм ВОС 101/102/103/106 або якщо залучено
  інструктора НЦ (тоді місцем вказується НЦ) — інакше попередження.
- Курси інструкторів — без ВОС, абревіатури з довідника `course`.

## 6. Превʼю (головний екран імпорту)

- Таблиця як у формі введення (02), але кожна клітинка показує **нормалізоване значення**, а при наведенні —
  сире значення з файлу і координату (`Лист "25.09", C12`).
- Фільтр "показати тільки рядки з помилками / попередженнями".
- Виправляти прямо тут (та сама сітка, ті самі гарячі клавіші й підказки).
- Масові дії: "усім рядкам з «польша» → Республіка Польща" (і запам'ятати як синонім).
- Зіставлення колонок редагується (перетягнути заголовок на поле); збережене зіставлення
  прив'язується до "відбитка" шаблону (набір нормалізованих заголовків) і застосовується автоматично
  наступного разу.
- Кнопка "Зафіксувати" активна, коли помилок 0 (або проблемні рядки явно виключені — виключені
  рядки теж зберігаються в поданні з позначкою, щоб було видно, що саме не прийняли).

## 7. Персональні дані

Файли адаптації містять ПІБ і звання. Такі колонки розпізнаються і **не зберігаються**: при імпорті
рядки агрегуються в кількості за (частина, місце, терміни, джерело надходження), а в `stored_file`
зберігається **знеособлена копія** (колонки ПІБ/звання/старший групи вичищені) замість оригіналу.
У логах ПІБ також не друкувати.
