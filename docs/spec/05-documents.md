# 05. Документи, які генерує система

Усі документи — з канонічних даних (`daily_counts` + події), параметри: орган, дата "станом на",
момент знань (за замовчуванням — зараз). Кожен згенерований документ зберігається в
`generated_document` (що, для кого, станом на, файл). Еталони лежать у
`source_files/Зразок/` — **вихід має відтворювати їх структуру**; золоті тести — на цих файлах
(див. 06).

Спільні реквізити (налаштування на рівні органу, редагуються адміном, підставляються автоматично):
гриф ("Для службового користування"; для презентацій — "ДЛЯ СЛУЖБОВОГО КОРИСТУВАННЯ (ОБМЕЖЕНО В
РОЗПОВСЮДЖЕННІ – ЛИШЕ ДЛЯ ЗБРОЙНИХ СИЛ УКРАЇНИ)"), "Додаток", "Прим. №1", блок "Вик.1 прим. на АБАК
№…", "Прим. № 1 – до справи", "Гриф обмеження доступу надано на підставі п.1.1 ПСІ – 2025",
"Виконано без чернеток та варіантів", підпис (посада, звання, ім'я ПРІЗВИЩЕ). У формі генерації
все це можна перевизначити на один раз.

Назва частини в документах: `short_name` + номер (`128 огшбр (А1556)`), якщо формат колонки
цього вимагає; у зведених — тільки `short_name`.

## Хвиля 1 (обов'язкові першими)

### D1. Щоденна зведена таблиця органу (xlsx)
Еталон: `source_files/Зразок/26.09/17 АК_39 тиждень_21.09-27.09.xlsx` (і 20 АК, 30 КМП, 7 КШР, ОТУ, ЧБП).
- Файл на **тиждень**: аркуш на кожен день (`21.09` … `27.09`), службові аркуші `початок`/`кінець`
  і `тижневий`.
- Денний аркуш: "<Орган>. Зведена таблиця підготовки станом на DD.MM.YYYY"; колонки БЗВП / Фахова /
  Адаптація × (Всього, Закінчують сьогодні, Почали сьогодні) + Примітка; рядок ВСЬОГО з формулами SUM.
- Друга секція: "Підрозділи, які знаходяться в штатному підпорядкуванні <органу>, але не виконують
  бойові завдання в смузі оборони УВ (с) "Південь"" (правило групування — 01) + рядок РАЗОМ.
- Тижневий аркуш: "Закінчили / Почали протягом тижня" — **формулами** `SUM(початок:кінець!C5)`, як в
  еталоні (люди потім правлять руками в Excel — формули мають жити).
- Примітки генеруються з подій дня ("Фах - 2 вс розпочали 25.09.2026; Адаптація - 1 вс хворий")
  у тому ж стилі, що в еталоні.

### D2. "Контролька" (xlsx, накопичувальна)
Еталон: `source_files/Зразок/26.09/Контролька (нвдпвднст).xlsx`.
Тиждень → день → орган → частина; колонки БЗВП / Фахова / Адаптація × (Всього, Закінчують сьогодні,
почали сьогодні, **вибули з різних причин**) + Примітка; підсумки формулами; закріплені панелі.

### D3. "Говорілка" — текст доповіді (docx)
Еталон: `source_files/Зразок/Говорілка_26.09.2026.docx`. Абзаци по слайдах, числа з пробілом-
розділювачем тисяч, відсотки цілі, зміни за добу `+6/−27/+74` (справжній мінус "−"), лідери
за частками. Текст — шаблон з підстановками; шаблон редагований адміном.

### D4. Презентація "Підготовка" (pptx)
Структура за еталоном даних `source_files/Зразок/Підготовка_26.09.2026.pptx`:
1. Загальна динаміка: 3 KPI-панелі (БЗВП / Фахова / Адаптація: станом на, зміна за добу, вчора → сьогодні),
   рейтинг органів з частками, загалом, кільцева діаграма складу найбільшого органу (топ-4 + "решта").
2. Огляд: таблиця ЧБП + панелі "Фахова підготовка" / "Адаптація" з розподілом за підпорядкуванням
   і "лідери у <органі>" (топ-4).
3…N. По слайду на орган (ОТУ "Одеса", 30 КМП, 17 АК, 7 КШР, 20 АК): таблиця частин
   (Станом на / Зміни за добу для кожного виду; формат змін `13/+4` = завершили/розпочали)
   + 4 панелі (БЗВП, Фахова, Адаптація, Загалом: Залучено / Завершують / Розпочинають).
   Правило згортання: показувати частини, поки таблиця влазить на слайд (≈9 рядків), решта —
   рядок "Інші (N підр.)" із сумами. N рядків — параметр.

**Стиль — строго за `docs/templates/presentation-style.pptx`** (не за стилем старої презентації):
- 16:9, 33.87 × 19.05 см;
- фон: темно-оливкові фото/текстури з еталона (витягнути зображення з еталона і використовувати
  як ресурси), панелі `#38331F`, найтемніше `#0E0C08`;
- акцент `#F39200` (заголовки розділів, цифри KPI, номер слайда в рамці, маркери списків, кутові скоби);
- текст: основний `#F7F5F0`, вторинний `#D2CCBC`, приглушений `#A8A08A`;
- шрифти: `UAF Sans` (основний), `UAF Sans SemiBold` (заголовки, великі цифри) — вбудувати/передбачити
  фолбек, якщо шрифту нема на машині перегляду;
- кожен слайд: емблема угруповання зліва вгорі, заголовок великими літерами, підзаголовок сірим,
  номер слайда в помаранчевій рамці справа вгорі, гриф "ДЛЯ СЛУЖБОВОГО КОРИСТУВАННЯ" дрібно внизу;
- титульний і фінальний слайди — як в еталоні (кутові скоби навколо тексту, "Слава Україні!");
- картки "01 / 02 / 03" з помаранчевою цифрою та тонкою помаранчевою рамкою — для переліків;
- KPI-плитки: велике помаранчеве число + підпис капсом дрібно + пояснення сірим.

## Хвиля 2

### D5. Додатки корпусу (xlsx) — еталони в `source_files/Зразок/Зразки на валідацію/`
- **Фах**: аркуші "Пройшли" / "Проходять" (Підрозділ, Місце, Посада, ВОС, ОВТ, Термін з/по,
  Кількість або План/Факт), підсумок по кожній частині, гриф/підпис.
- **БпС** (щочетверга): "Завершилась" / "Навчаються" — Тип БпАК, ВОС, ВЧ (номер + назва), Місце
  (номер + назва), Терміни, Викликали / Прибуло до НЦ / Успішно завершило (або Проходять), Примітки;
  секції "безпосереднього" / "оперативного" підпорядкування.
- **КВід**: укомплектованість командирами відділень (штат, список, наявність, %, мають підготовку
  "48 (84%)", проходять, заплановано, потребують) — дві секції.
- **ІВС**: укомплектованість і навченість груп інструкторів + стажування.
- **Терміни проведення підготовки** (для УВ(с)): по частинах БЗВП / Фахова / Адаптація з кількістю,
  термінами, місцем, розподілом о/с, спеціальністю; об'єднані клітинки по частині.

### D6. Передані частини
Звіт по частинах зі статусом `transferred`: кому передані, в яких заходах підготовки беруть участь,
кількості — для доповіді командувачу.

## Технічні рекомендації (рішення зафіксувати в `.claude/decisions/`)
- xlsx: `rust_xlsxwriter` (формули, об'єднання, стилі, закріплення панелей).
- docx: шаблон (docx з плейсхолдерами) + підстановка в XML, або `docx-rs`.
- pptx: зрілої Rust-бібліотеки нема. Рекомендація — **шаблонний підхід**: pptx з еталонними
  слайдами-макетами (іменовані фігури, як у старій презентації: `kpi-bzvp-current`, `rank-label-1`…),
  генератор розпаковує zip, клонує потрібні слайди, підставляє текст/розміри смуг/значення діаграм
  у XML. Альтернатива (Python-сайдкар з python-pptx) — тільки якщо шаблонний підхід впреться в стіну;
  це окремий процес і окрема пам'ять — зважити.
- Генерація важких документів — у фоновій задачі з прогресом, не в запиті.
