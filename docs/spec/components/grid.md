# Grid — колонки, ширини, drawer, дати (розділ Б)

Переробка `widgets::group_grid::Grid` колонка за колонкою (feedback користувача, 2026-09-30,
розділ Б — за розділом А, `docs/spec/components/select.md`). Той самий `Grid`, обидві сторінки
(`/training-form`, `/import`) — зміни тут зачіпають обидві.

## 1. Колонки — таблиця (9 живих треків, було 11 → 15)

Секундарні поля (розподіл/організатор/підстава/примітка) прибрано з живих треків — лишаються
тільки в drawer (`RowEditor`, уже повний). Composition вже й був лише в drawer.

**"Частина" прибрана з колонок рядка (2026-09-30, `.claude/decisions/
sender-org-once-per-submission.md`)** — обирається ОДИН раз у тулбарі сторінки, не на рядок;
клавіатурний/взаємодійний контракт клітинок, що лишились, тепер — `docs/spec/components/
grid-interaction.md` (окремий документ, не цей).

## 2. `Combobox::Input` — "інпут сам тригер"

Розширення (не новий компонент) — третій вимір поруч із `variant`/`searchable`:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub enum ComboboxMode {
    #[default]
    Trigger,   // кнопка відкриває панель, пошук ВСЕРЕДИНІ (розділ А)
    Input,     // видимий елемент — сам <input>, типізація фільтрує/фетчить
}
```

У режимі `Input`:
- немає окремої кнопки-тригера — сам `&lt;input class="combobox__input"&gt;` є видимим елементом,
  той самий портал-панель відкривається знизу при фокусі/вводі (той самий `use_popover_position`);
- компонент НЕ фільтрує список сам (на відміну від `Trigger`+`searchable`) — `items` приходять
  уже відфільтрованими ззовні; новий опційний проп `on_query_change:
  Option&lt;Callback&lt;String&gt;&gt;` — викликач сам тримає `Resource`/`Signal&lt;Vec&lt;ComboboxItem&gt;&gt;`
  (той самий патерн, що вже в `OrgAutocomplete` сьогодні — переносимо, не винаходимо);
- `value: Signal&lt;String&gt;` лишається "обраний id" (як у `Trigger`), але видимий текст інпута —
  ОКРЕМИЙ `label`-проп (`#[prop(into)] label: Signal&lt;String&gt;` +
  `on_label_input: Callback&lt;String&gt;`) — бо під час пошуку текст інпута й обране значення
  розходяться (шукаєш "вамп", бачиш "ВОС 218" лише після вибору) — той самий поділ, що вже в
  `OrgAutocomplete` (`label`/`on_label_input`);
- клавіатура — той самий контракт, що вже є (`on_trigger_keydown`), лише прив'язаний до `input`,
  не до `button`.

**`ComboboxItem.value: String` — кодування id.** Компонент лишається domain-agnostic (не знає
`org_id: i32` чи `VosPositionCourseKind`), тож виклик сам кодує:
- Частина: `value = org_id.to_string()`, розбір на `on_change` — `value.parse::&lt;i32&gt;()`;
- ВОС/посада/курс: `value = format!("{kind_prefix}:{id}")` (`"vos:218"`/`"position:.."`/
  `"course:.."`), розбір — split по `:` + матч на префікс.

Свідомий компроміс: не узагальнюю `Combobox` на generic `T` заради ОДНОГО вживання з нетривіальним
id — це роздуло б компонент. Тонкі домен-обізнані обгортки (`OrgAutocomplete`,
`VosPositionCourseAutocomplete`, публічний контракт БЕЗ ЗМІН) лишаються в
`widgets/group_grid/autocomplete.rs`, всередині рендерять `&lt;Combobox mode=Input .../&gt;`
замість власної розмітки.

## 3. Колонка дій

```
┌──────┐
│  ⋮⋮  │  ← номер рядка (текст, `t-xs fg-muted num`)
│  ▸  │  ← кнопка розгортання (≥32×32px хіт-зона), tooltip "Деталі рядка (Ctrl+E)"
│  ●  │  ← індикатор помилки (крапка danger) — лише коли є client-side помилка
│  ⋯  │  ← меню рядка (дублювати/видалити), власний маленький popover, portal
└──────┘
```

Sticky (`position: sticky; left: 0`), той самий z-шар, що інші поповери (`z-dropdown` замало —
має бути НАД рештою рядків під час скролу, але ПІД відкритою панеллю комбобокса — новий шар
`z-sticky` між `base` і `z-dropdown` в `style::TOKENS`, якщо готового не вистачає, інакше
переюзати наявний найнижчий).

**Індикатор помилки** — об'єднує: (а) client-side funnel-порушення (§5) на цьому рядку,
(б) невалідний `date_range_cell` на цьому рядку. НЕ перевіряє серверні помилки (ті приходять
лише при Ctrl+Enter і показуються окремим рядком під сіткою, як зараз).

**Меню рядка** — кнопка `⋯` відкриває маленький `Portal`+2 пункти (Дублювати/Видалити), той
самий `use_popover_position`, але БЕЗ `Combobox` (це вибір ДІЇ, не значення зі списку — інша
семантика, не value-picker). Видалити → `components::Dialog` підтвердження (вже є компонент,
не новий модальний примітив) — раніше Ctrl+Delete видаляв без підтвердження всупереч спеці
(02-input-forms-ux.md: "з підтвердженням") — тепер і гаряча клавіша, і пункт меню йдуть через
той самий підтверджувальний діалог.

## 4. `date_range_cell` — "З"/"По" пов'язані

Домен-обізнаний компонент у `widgets/group_grid/` (НЕ в `components/` — `components/` не знає
домену, а гнучкий розбір дат — це `domain::dates`). `components::DatePicker` лишається БЕЗ ЗМІН
(суворий `дд.мм.рррр`-формат, чинно працює для "Станом на" — той самий компонент, той самий
режим `field`, нічого чіпати не треба, п.4's останнє речення вже виконане).

Анатомія: два in-cell текстові поля (З/По) з тією самою маскою-в-процесі-набору, що вже в
`DatePicker` — АЛЕ на відміну від нього приймають commit і при НЕПОВНОМУ вводі ("18.08" без
року) через `domain::dates`:
- `on_change`/blur поля "З": пробує `domain::dates::parse_maybe_range(text, as_of)` — якщо
  результат "діапазон", заповнює ОБИДВА поля одразу (спека: "18.08-09.10" в "З" розкладається
  на обидві колонки); якщо ні — одиночна дата через той самий модуль, з висновком року з
  `as_of` (03-import-validation.md).
- "По" перевіряється: якщо `по &lt; з` — `invalid`-стан (той самий клас, що `Combobox`/
  `DatePicker` вже мають), НЕ тихе переставляння значень.
- Спільна календар-панель (portal, `hooks::use_popover_position`) відкривається з будь-якого
  поля, підсвічує весь діапазон [з, по] у сітці днів, один місяць видно за раз.
- Клавіатура в календарі: стрілки — день, PgUp/PgDn — місяць, Enter — вибір і перехід до
  наступного пов'язаного поля (з "З" на "По"), Esc — закрити; кнопка "сьогодні".

## 5. Числа

`План`/`Прибуло`/`Навчаються` — права юстиція (новий рецепт `.cell__number { text-align: right }`
— нема атома для text-align, лише `justify-*` для flex), `num`-атом (tabular-nums). Порожнє
значення показує `placeholder="—"`, НЕ `"0"` (нуль — це справжній нуль, введений явно).

Client-side funnel: `domain::validation::validate_funnel_order(planned, arrived, in_training)`
(уже є, WASM-сумісна) викликається реактивно (`Signal::derive` на трійці лічильників рядка) —
при `Err(FunnelOrderViolated)` підсвічує ОБИДВІ залучені клітинки (`arrived`/`in_training`)
червоною рамкою (`invalid`-клас) і додає індикатор у колонку дій (§3). Це той самий виклик,
що сервер уже робить у `backend/repo/groups.rs:276` — переносимо виклик клієнту, не дублюємо
логіку правила.

## 6. Sticky / scroll / видимість колонок

- `.grid__body` отримує обмежену висоту (`max-height: 70vh`) + `overflow-y: auto` (зараз скрол
  на всій сторінці) — заголовок стає `position: sticky; top: 0` ВСЕРЕДИНІ цього контейнера.
  `visible_count`-приріст (поточна "віртуалізація", `grid.rs`) не змінюється — той самий тригер
  через навігацію клавіатурою.
- Ширини колонок — `RwSignal`-стан у `columns.rs`, рендериться через
  `style:grid-template-columns=move || ...` (динамічний рядок — легітимний `style:`-виняток,
  той самий, що вже в `combobox.rs`; архітектурний тест ловить лише буквальний `style="..."`).
  Персистентність — `localStorage` (ключ `taktoblik.grid.v1`, `#[cfg(target_arch="wasm32")]`-
  гейт, той самий патерн, що `set_theme` у `styleguide.rs`) — per-viewer зручність, не потребує
  серверної персистентності.
- Тіні країв (коли залишається горизонтальний скрол) — псевдоелементи на обгортці `.grid`,
  видимість перемикається через `scroll`-listener (`scrollLeft`/`scrollWidth`/`clientWidth`).
- Перемикач "показати колонки" — маленький тулбар НАД заголовком сітки, усередині `Grid` (не
  чекає на Етап 7.5's сторінковий `Toolbar` — тут лише кнопка + чекбокс-список).
- Sticky ліворуч: колонка дій (`left: 0`) + "Частина" (`left: {ширина дії}px`) — нові рецепти
  в `main.css`, не атоми (нема шкали для довільних px-зсувів залежно від сусідньої колонки).

## 7. "+ Рядок"

Новий рецепт кнопки під сіткою, вирівняний з таблицею (не на всю ширину як зараз), з підказкою
клавіші (`&lt;kbd&gt;` — той самий "шильдик обладнання" мотив, що вже є для інших гарячих клавіш).

## 8. Що НЕ змінюється в цьому розділі

- `Grid`'s публічний проп-список (`editable`/`next_id`/`active_cell`/`before_mutate`) — не
  чіпається, обидві сторінки (`/training-form`, `/import`) продовжують викликати так само.
- `RowEditor` (drawer) — контент не перебудовується (уже повний за фактом розвідки), лише
  зовнішня інтеграція (Ctrl+E, індикатор, фокус-повернення).
- `components::DatePicker`/`components::Select` — не видаляються (Select лишається доступним
  для інших сторінок, які ще не мігрували на `Combobox`).
