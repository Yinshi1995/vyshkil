# Select / Combobox — анатомія, стани, клавіатура

Переробка з нуля (feedback користувача, 2026-09-30) — попередній `components::Select` патчився
точково (колізія з в'юпортом, ширина в грід-колонці, тема скролбару) і в підсумку "не приймається"
загалом. Цей документ — спершу дизайн, потім код (07 §00): анатомія й поведінка, звірені з
референсних реалізацій, перш ніж чіпати Leptos-код.

## 1. Що взято з референсів

| Джерело | Що конкретно бере taktoblik | Чому саме звідти |
|---|---|---|
| **Radix UI Select** | Портал для Content (ніколи не обрізається `overflow` таблиці); Popper-подібна колізія — авто-flip сторони, авто-shift уздовж осі вирівнювання, щоб лишитись у в'юпорті | Найчистіша модель "тригер + портал + Popper" — саме та причина, з якої наш попередній Select обрізався в клітинках Grid |
| **Headless UI Combobox** | "Інпут сам є тригером" — на відміну від Listbox (окрема кнопка відкриває), тут текстове поле й фільтрація живуть в ОДНОМУ елементі, тому в'юзер не перемикається між "полем" і "кнопкою" | Довідники (частина/ВОС) уже мають окремий `OrgAutocomplete`, що робить те саме, але без порталу/колізії — Combobox-режим нового компонента замінить його, не дублюватиме |
| **React Aria useComboBox/useSelect** | `aria-activedescendant`-модель клавіатури: фокус НЕ переходить у список, підсвічений пункт позначається `aria-activedescendant` на самому інпуті/тригері — це і дає "Tab вибирає й переходить далі", не розриваючи фокус між полями сітки; чіткий поділ menuTrigger (focus/input/manual) | Найсуворіша, найдокладніше специфікована клавіатурна модель з усіх п'яти — знімає здогадки про Home/End/typeahead |
| **Ark UI (zag.js) Select** | Явний поділ `Positioner` (`flip`+`shift`+`size` middleware) від `Content` — позиціонування як окремий, конфігурований шар, не вплетений у сам компонент | Підтверджує, що позиціонування має бути ОКРЕМИМ хуком (як уже й був `use_floating_position`, лишень тепер рахує пікселі для порталу, не CSS-класи для in-flow) |
| **Mantine Select/Combobox** | (а) вбудований `searchable` перемикач замість двох окремих компонентів для короткого списку vs довідника; (б) двострічковий item (назва + приглушене пояснення) — готовий патерн для "вамп → ВОС 218, бо Vampire"; (в) архітектура "один `Combobox`-двигун, кілька конкретних `Target`" | Найближче до того, що потрібно тут: ОДИН компонент з `searchable`-прапорцем, а не Select+Combobox як дві різні сутності |

**Висновок архітектури**: один компонент `Combobox` (позиціонування+клавіатура+список), з двома
`mode`: `Trigger` (кнопка, значення обирається зі списку — заміна нинішнього `Select`) і `Input`
(текстове поле само фільтрує — заміна нинішнього `OrgAutocomplete`/`VosPositionCourseAutocomplete`).
Обидва — той самий список/портал/позиціонування/клавіатуру, різниться лише "що є тригером".

## 2. Анатомія

```
<Combobox>                              (кореневий контейнер, position:relative лише для якоря)
  ├─ Target                             (кнопка — mode=Trigger; або <input> — mode=Input)
  │    └─ Chevron                       (у Trigger — завжди; у Input — опційно)
  └─ Portal → Positioner                (position:fixed, пікселі рахує use_popover_position)
       └─ Content
            ├─ SearchInput              (лише якщо searchable=true І mode=Trigger; у mode=Input
            │                            саме поле Target — воно ж і є пошуком)
            ├─ Group* (label + Item*)   (опційно, для згрупованих довідників)
            ├─ Item*                    (label + опційний muted-рядок пояснення + checkmark)
            └─ Empty                    ("Нічого не знайдено" + опційна пропозиція)
```

## 3. Два режими вживання (не "два компоненти")

- **`in-cell`** (Grid-клітинка): `Target` заповнює клітинку рівно по ширині й висоті рядка, без
  власної рамки/підкладки; шеврон з'являється лише на hover/focus; текст обрізається "…" +
  нативний `title`-tooltip. Ніколи не ширший за колонку й не вищий за рядок (немає власного
  `min-width`, на відміну від нинішнього — саме це ламало вирівнювання).
- **`field`** (форми/тулбари): самостійне поле з рамкою/підкладкою, як і нинішній `.select__trigger`
  візуально, але тепер із порталом і `searchable`.

## 4. Позиціонування (портал, `leptos::portal::Portal`)

`Content` рендериться в `document.body` через `<Portal/>` (Leptos 0.7 вже має цей примітив —
`leptos::portal::Portal`, перевірено в `leptos-0.7.8/src/portal.rs`), тому НІКОЛИ не обрізається
`overflow` жодної таблиці/картки. Позиція рахується новим хуком `hooks::use_popover_position`
(заміняє/розширює `use_floating_position` — той рахував лише CSS-класи для in-flow панелі, цей
рахує РЕАЛЬНІ пікселі для `position:fixed` портальованого елемента):
- на відкриття — `trigger.get_bounding_client_rect()` → `top`/`left`/`width` для
  `position:fixed` (viewport-відносні координати з `getBoundingClientRect` збігаються з системою
  координат `fixed` — не треба враховувати scroll-offset сторінки);
- **flip**: якщо місця знизу < порогу (висота контенту, обмежена `max-height`) і згори більше —
  `bottom = viewport_height - trigger.top` замість `top`;
- **shift**: якщо контент вужчий за `max(trigger.width, content.width)` і вилазить за правий край
  в'юпорту — притиснути до правого краю в'юпорту (не тригера — на відміну від `align-end` у
  старому хуку, тут немає "розмір колонки", лише "розмір екрана", бо портал);
- **size**: `max-height` контенту обмежується доступним простором (`min(280px, простір_до_краю)`),
  не фіксованим числом — довгий довідник (40+ рядків) не виштовхне себе за екран навіть коли
  згори/знизу мало місця;
- **close on scroll**: якщо користувач скролить СТОРІНКУ (не сам список) поки відкрито — закрити
  (найпростіший робастний вибір при `position:fixed`, той самий, що в більшості бібліотек без
  повного resize/scroll-observer перерахунку).

## 5. Клавіатура (React Aria модель, узгоджено з 02-input-forms-ux.md)

| Клавіша | Закрито | Відкрито |
|---|---|---|
| `↓`/`↑` | відкрити, підсвітити поточне/перше | пересунути підсвітку (не переносить фокус — `aria-activedescendant`) |
| `Alt+↓` | відкрити (той самий шорткат, що вже в шпаргалці) | — |
| `Home`/`End` | — | підсвітити перший/останній |
| Друк символу | — (mode=Trigger, не searchable) | typeahead — стрибок на перший збіг |
| Друк символу | mode=Input АБО searchable=true | живий фільтр списку (не typeahead) |
| `Enter` | відкрити | обрати підсвічене, закрити |
| `Tab` | звичайний перехід | обрати підсвічене й ПІСЛЯ ЦЬОГО перейти (той самий контракт, що вже описаний у `Grid`'s `on_keydown`-форвардингу — не змінюється) |
| `Esc` | — | закрити без вибору |
| Клік поза | — | закрити без вибору |

`menuTrigger` (React Aria термін) для `in-cell`+`Grid`: `manual` — стрілки, поки закрито,
форвардяться в Grid (як і зараз через `on_keydown`), відкриває лише клік/`Alt+↓`/Enter/Space.
Для `field` (самостійне вживання, не в Grid): `focus`-подібний — стрілки одразу відкривають.

## 6. Item — двострічковий патерн (Mantine-подібний)

```
┌──────────────────────────────────────┐
│ ВОС 218 — зовнішній пілот (оператор)  │  ← основний рядок
│ бо "Vampire" → 218                    │  ← приглушений рядок (опційний, з `why`)
└──────────────────────────────────────┘
```
Checkmark — праворуч, лише коли `is_selected`. Групи (`Group`) — заголовок капслоком, приглушений
колір, без рамки/фону (той самий принцип "щільні поверхні спокійні", 08 §6).

## 7. Стани для `/styleguide` (обов'язкові, перш ніж чіпати Grid)

Обидва режими (`in-cell`/`field`) ×: закритий, hover, focus, відкритий (короткий список),
відкритий (з пошуком), порожній результат пошуку, disabled, invalid (червона рамка/індикатор),
довгий текст значення (перевірка ellipsis+tooltip), 300 елементів (перевірка продуктивності
рендеру списку — чи не гальмує typeahead/скрол).

## 8. Що НЕ переробляється в цьому розділі

`OrgAutocomplete`/`VosPositionCourseAutocomplete` (widgets/group_grid/autocomplete.rs) —
замінюються новим `Combobox mode=Input` ЛИШЕ після інтеграції в Grid (розділ Б), не одночасно з
побудовою в styleguide (розділ А) — щоб не зламати вже робочі шляхи `search_orgs`/
`search_vos_position_course` до того, як новий компонент перевірений ізольовано.
