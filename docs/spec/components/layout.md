# Лейаут сторінок — PageHeader, Toolbar, ширина контенту (Етап 7.5)

Переробка каркаса сторінок (feedback користувача, 2026-09-30, розділ В брифу) — після розділів
А (`select.md`) і Б (`grid.md`). Дефекти, які мають зникнути: величезний заголовок, розкидані
контролі різного розміру, контент обмежений вузьким `max-width`, хоча сітці (`/training-form`)
потрібна вся ширина — саме це заважало Section Б's sticky/scroll-верстці показати повний ефект
на широких екранах (`.claude/decisions/grid-column-strategy.md`, "відомий, свідомо НЕ виправлений
зараз момент").

## 1. Анатомія

```
<Header/>                              (app.rs, вже є — лого+нав+ActorSwitcher, НЕ чіпається)
<main>                                 (app.rs, вже є — тепер БЕЗ власного max-width, §3)
  <PageHeader>                         (нове)
    breadcrumbs?                       ("Головна / Картка частини")
    title                              (компактний, не `<h1>` величезний)
    subtitle?                          ("станом на …, актор …" — контекст, не декор)
    actions?                           (справа — дії сторінки, 0-2 кнопки)
  <Toolbar>?                           (нове, опційний — лише сторінки з фільтрами/діями над даними)
    left                               (фільтри/параметри: "Станом на", тип подання)
    right                              (дії: Імпорт/Зберегти/Шпаргалка)
  <PageContent width=...>              (нове — обгортка з типом ширини, §3)
    {решта сторінки}
```

## 2. `PageHeader`

- `breadcrumbs: Vec<(String, Option<String>)>` — `(label, href)`; `href=None` для поточної
  сторінки (не клікабельна, просто текст). Порожній `Vec` — без хлібних крихт (головна сторінка).
- `title: String` — компактний заголовок (менший за нинішній `<h1>` величезний — новий рецепт
  `.page-header__title`, не той самий розмір, що `<h1>` на styleguide/головній).
- `subtitle: Option<String>` — один рядок контексту під заголовком ("станом на 28.09.2026 · 241
  обр ТрО"), приглушений колір, не декор.
- `children` (опційно) — дії сторінки праворуч (0-2 кнопки, `.btn--primary`/`.btn--outline`).

## 3. `PageContent` і типи ширини

`app.rs`'s `<main>` більше НЕ має власного `max-width` (те, що зараз ламає повну ширину сітки) —
кожна сторінка сама вирішує через `<PageContent width=...>`:

| Тип | Ширина | Хто |
|---|---|---|
| `ContentWidth::Data` | повна (`width:100%`, без `max-width`) | сітки, імпорт, майбутні розбіжності |
| `ContentWidth::Detail` | `max-width:1200px`, готова під 2 колонки (`.page-content--detail` — `display:grid; grid-template-columns: 2fr 1fr` на `md:`+) | картка частини |
| `ContentWidth::Reading` | `max-width:720px` (вузька, як і було де доречно) | довідка/стайлгайд-подібний текст |

`main`'s старий `max-width:1200px` переїжджає в `.page-content--detail`/`.page-content--reading`
як їхня ВЛАСНА межа — `Data` явно її не успадковує. Головна/довідники/ВОС-підказка (Etap 7.5 §4
"пройтися по ВСІХ сторінках") ще НЕ мігрували в цьому проході (розділ В's власна ЗУПИНКА —
лише `/training-form` і `/org/:id` зараз) — доти вони рендеряться без `PageContent`-обгортки
взагалі, тобто без ЖОДНОГО max-width (регресія ширини на них — очікувана, тимчасова, до
завершення розкатки на решту сторінок).

## 4. `Toolbar`

- `left: Children`, `right: Children` — дві групи, `justify-content: space-between`.
- Усі контролі всередині (кнопки/`Combobox`/`DatePicker`/`FileDropzone`) вирівнюються по
  ВИСОТІ — спільний `--control-height` (новий токен, `40px`, `style::TOKENS`), кожен рецепт
  (`.btn`, `.combobox__trigger--field`, `.combobox__field--field`, `.date-picker__field`)
  дістає `min-height: var(--control-height)` замість покладатись на padding, щоб різні шрифти/
  border-width не давали різну фактичну висоту.
- `FileDropzone` — виняток (не кнопка, більша зона) — лишається як є, не підпорядковується
  `--control-height`.

## 5. Кнопки — ієрархія (§ брифу "розміри кнопок")

Одна `.btn--primary` на сторінці (головна дія — "Зберегти"), решта — `.btn--outline`
(secondary) або НОВИЙ `.btn--ghost` (третинна дія: без рамки, лише текст+hover-підсвітка,
напр. "Шпаргалка", "Колонки"). Усі три — той самий базовий `.btn` (спільна висота/шрифт),
лише фон/рамка різні.

## 6. Розкатка на всі сторінки (розділ В)

Пілот (`/training-form`, `/org/:id`) підтверджено користувачем ("ок") — розкатано на решту:

| Сторінка | `ContentWidth` | `Toolbar` | Чому |
|---|---|---|---|
| `/training-form` | `Data` | так | сітка, потрібна вся ширина |
| `/import` | `Data` | так | той самий `Grid` |
| `/org/:id` | `Detail` | ні | картка, дві колонки історії |
| `/` (головна) | `Detail` | ні | картки+дерево, не таблиця на всю ширину |
| `/dictionaries` | `Detail` | ні | картки-таблиці словників |
| `/vos-lookup` | `Reading` | ні | однопільний пошук, вузька колонка |

Усі 6 сторінок мігровано, один коміт на сторінку.
