# Контракт клавіатурної поведінки сітки

Постійний стандарт для ВСІХ сіток проєкту (не лише `widgets::group_grid` — будь-яка майбутня
таблиця з редагованими клітинками). Записано за прямою вимогою користувача після відхилення
переробки `/training-form` — форма не пройшла ручну клавіатурну перевірку перед здачею
(`.claude/decisions/` — урок у `MEMORY.md`). Зміна сітки/типу клітинки без оновлення відповідного
e2e-сценарію (`e2e/tests/`) — відхиляється при рев'ю.

## 1. Навігація

- `Tab` / `Shift+Tab` — наступна/попередня редагована клітинка; з останньої клітинки рядка — перша
  клітинка НАСТУПНОГО рядка. З останньої клітинки ОСТАННЬОГО рядка — створює новий рядок і ставить
  туди фокус.
- Стрілки `↑`/`↓` (коли випадайка закрита) — та сама колонка в сусідньому рядку; `←`/`→` при
  курсорі на краю тексту — сусідня клітинка.
- Фокус-клітинку видно ЗАВЖДИ (кільце акценту); фокус ніколи не губиться після дії (вибір,
  закриття поповера, збереження, помилка).
- `Enter` на клітинці в режимі навігації — редагування; `Esc` — скасувати редагування/закрити
  поповер БЕЗ зміни значення; `F2` — редагувати без стирання поточного значення.

## 2. Клітинка-вибір (`Combobox` in-cell)

- Фокус (клік АБО прихід `Tab`-ом) → одразу відкритий список: недавні/найчастіші значення цього
  актора зверху, далі весь довідник; перший елемент підсвічений. Друк не потрібен, щоб побачити
  список.
- Друк фільтрує (нечіткий пошук за `alias`, як у 02 §3), підсвічує збіг.
- `↑`/`↓` — рух по списку; `Enter` — вибрати підсвічене й перейти до наступної клітинки; `Tab` —
  те саме (вибрати підсвічене Й перейти далі); `Shift+Tab` — назад БЕЗ вибору.
- `Esc` — закрити без зміни значення.
- Якщо значення вже вибране, і людина просто проходить клітинку `Tab`-ом (не відкриваючи список
  свідомо) — значення НЕ змінюється і НЕ стирається.
- Поповер — через portal, ніколи не обрізається контейнером, фліпається вгору біля нижнього краю
  в'юпорту, ширина ≥ ширина клітинки.

## 3. Клітинка-дата (маска `дд.мм.рррр`)

- Приймає лише цифри; крапки ставляться автоматично під час вводу (`"1808"` → `"18.08."`, далі
  рік).
- Рік: введено 2 цифри → префікс `"20"` + вони (`"26"` → `"2026"`); рік завжди `20xx`; можна ввести
  одразу всі 4 цифри.
- Поле показує маску-підказку `"дд.мм.рррр"` приглушеним кольором, заповнені частини — основним.
- Валідація ПО ЧАСТИНАХ під час вводу (не лише після завершення):
  - місяць `01`–`12`; перша цифра місяця `> 1` → автопідстановка `"0X"`;
  - день `01`–`31` з урахуванням місяця (30 для квітня/червня/вересня/листопада, 28/29 для лютого
    — перевірка високосного року ПІСЛЯ введення року); перша цифра дня `> 3` → автопідстановка
    `"0X"`.
  - Неможлива дата (`31.04`, `29.02` у невисокосний рік) → клітинка в стані помилки з поясненням у
    tooltip, збереження рядка блокується.
- `Backspace` стирає цифру РАЗОМ із зайвою автопроставленою крапкою (не залишає `"18.."`).
- Вставка (`Ctrl+V`) нормалізує розпізнані формати: `"18.08.2026"`, `"18/08/26"`, `"2026-08-18"`.
- Діапазон в одній клітинці: `"18.08-09.10"` у "З" розкладає значення на "З" і "По" (той самий
  `domain::dates::parse_maybe_range`, що вже є).
- Календар (`Alt+↓` або клік по іконці) — повністю клавіатурний: стрілки — дні, `PgUp`/`PgDn` —
  місяці, `Enter` — вибір, `Esc` — закрити. "По" не пропонує дні РАНІШЕ за "З": недоступні дні
  затемнені, діапазон між ними підсвічений.
- Рік без явного вказання (ручний ввід без року, імпорт/вставка `"18.08"`) — за правилом з 03 §4
  (`domain::dates::parse_date`).
- Датапікер повністю вміщається у свою клітинку: іконка календаря — всередині клітинки, праворуч,
  видима лише на hover/фокус клітинки (у спокої прихована — не забирає місце в тексті); ширина
  колонки дати розрахована під `"31.12.2026"` + іконку, не менше.

## 4. Числові клітинки

- Лише цілі `≥ 0`; вирівнювання праворуч, `tabular-nums`. Порожньо ≠ `0` (порожнє поле в спокої —
  порожнє, не `"0"` і не `"—"`).
- Якщо "План" заповнено, а "Прибуло"/"Навчаються" порожні — при виході з клітинки "План" (`Tab`)
  підставляється те саме значення приглушеним кольором як ПРОПОЗИЦІЯ; наступний `Tab` приймає її
  (як звичайний перехід), ручний ввід — перезаписує.
- Порушення порядку воронки (план ≥ прибуло ≥ навчаються) підсвічує ОБИДВІ порушені клітинки.

## 5. Рядок

- Службові елементи рядка (номер, "відкрити" ⤢, меню ⋮) стоять в ОДИН горизонтальний ряд у вузькій
  колонці-жолобі зліва; висота рядка ФІКСОВАНА й однакова для всіх рядків (comfortable ~36px,
  compact ~32px — перемикач щільності в тулбарі, `docs/spec/components/data-table.md`). У спокої
  видно лише номер; "відкрити" і меню — на hover/фокус рядка.
- Помилка в рядку — червона крапка в жолобі + підсвічена клітинка + зрозумілий текст і в tooltip
  клітинки, і у зведенні під сіткою (`"Рядок 3, «По»: 31.04 — у квітні 30 днів"`).
- `Ctrl+Enter` при наявних помилках — фокус переходить на ПЕРШУ помилкову клітинку, нічого не
  зберігається (ні чернетка, ні коміт).

## 6. Поза обсягом цього документа

Формат/кольори клітинок і тулбару, чипи типів колонок, empty/loading-стани всієї таблиці —
`docs/spec/components/data-table.md` (візуальний шар, не поведінковий). Цей документ — лише
клавіатура/фокус/валідація; візуальні класи змінюються окремо, контракт тут — ні.
