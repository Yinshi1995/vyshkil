# Вибір файлу (`components::FileDropzone`)

Переробка з нуля (feedback користувача — клік по старій зоні не відкривав системний діалог;
`.claude/decisions/label-for-file-input.md` пояснює чому саме `<label for>`).

## 1. Чому так

Стара реалізація: прихований `<input type="file">` (`display:none`) + програмний `.click()` з
`stop_propagation()`-форвардингом на клацання/Enter/Space. Ця зв'язка задокументовано ненадійна —
частина браузерів/вебвʼю не відкриває системний діалог за програмним `.click()` на елементі, який
ніколи не рендериться (`display:none` вилучає елемент з layout-дерева повністю). Діагностика цієї
сесії (Playwright/Chromium) не змогла відтворити точний репорт користувача — клік у автоматизації
відкривав діалог і на старому коді — але патерн лишається об'єктивно крихким і користувач явно
попросив саме `<label for>`, тож переробка виправдана незалежно від підтвердження конкретного
репро.

Нове: `<label>` ОБГОРТАЄ реальний `<input type="file">` (той самий "visually-hidden, не
`display:none`" патерн, що `components::Checkbox`) — клік будь-де в лейблі і клавіатура
(Enter/Space на сфокусованому інпуті) працюють нативно, БЕЗ жодного JS-форвардингу.

## 2. Анатомія

- `.dropzone-wrap` — контейнер (тригер + помилка + чип, вертикальний стек).
- `.dropzone` (`<label>`) — тригер, два варіанти:
  - `--compact`: кнопка в тулбарі таблиці (іконка + текст, висота `--control-height`).
  - `--zone`: велика пунктирна зона там, де файл — головна дія сторінки (`/import`).
- `.dropzone__input` — реальний `<input type="file">`, visually-hidden (`position:absolute;
  opacity:0`, вкриває весь `.dropzone`) — не `display:none`.
- `.dropzone-overlay` (portal) — повноекранний приймач на `dragenter` БУДЬ-ДЕ на сторінці (не лише
  над тригером) — замінює стару завжди-розгорнуту коробку.
- `.file-chip` — обраний файл: назва, розмір, стадія (читання/розбір/готово/помилка), ✕.

## 3. Стадії (`FileStage`)

Компонент сам знає лише "файл обрано" (імʼя/розмір, миттєво в `on:change`/`drop`). Стадії
читання-на-клієнті/розбору-на-сервері знає лише виклик (async, за межами компонента) — контрольований
проп `stage: Signal<FileStage>` (`Idle|Reading|Parsing|Ready|Error(String)`), компонент лише малює
чип за ним. Той самий поділ відповідальності, що решта `components/` — плоскі пропси, жодного
доменного знання.

## 4. Перетягування — на рівні `window`, не елемента

`dragenter`/`dragleave`/`dragover`/`drop` слухаються на `window` (не на `.dropzone`) — "перетягніть
БУДЬ-КУДИ на сторінку", не лише над маленькою кнопкою. Лічильник (не булевий прапорець) — захист від
фліку, коли курсор перетинає дочірні елементи під час перетягування. Порожній `DataTransfer` (без
типу `Files`) навмисно НЕ показує приймач — перетягування виділеного тексту/посилання не має
відкривати оверлей імпорту.

## 5. Валідація на межі (клієнт, до звернення до сервера)

- Розширення файлу проти `accept` (напр. `.xlsx`) — регістронезалежний `ends_with`.
- Розмір проти `max_size_mb` (проп, дефолт 20 МБ).
- Обидві — одразу після вибору/drop, ДО `on_file`; помилка малюється в `.dropzone-wrap`, `on_file`
  не викликається для невалідного файлу.

## 6. Повторний вибір того самого файлу

`<input>.value` скидається (`set_value("")`) одразу після обробки `change` — інакше вибір ТОГО
САМОГО файлу вдруге не шле нову подію `change` (реальна ненадійність старої реалізації, знайдена
заразом із переробкою).

## 7. Стани в `/styleguide`

Обидва варіанти (`Compact`/`Zone`) × стани: порожньо, обрано (готово), обрано (помилка розбору),
клієнтська помилка типу/розміру, disabled, перетягування (оверлей).

## 8. Поза обсягом

Множинний вибір файлів (`multiple`) — жоден поточний споживач цього не потребує; серверна
multipart-передача (файл і зараз читається в байти на клієнті й іде як `Vec<u8>` в аргументі
`#[server]`-функції — без змін).
